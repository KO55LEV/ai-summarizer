Workflow Visual

YouTube transcript pipeline, step by step

This page shows the exact flow used when a user schedules a YouTube transcript. The workflow first checks for a native transcript, then either imports it or falls back to the manual pipeline: download video, extract audio, transcribe with Whisper, and import the transcript.

Entry point
POST /api/transcripts/youtube/schedule

Creates or reuses a `youtube.transcript` workflow.

Fallback path
Native transcript unavailable

The worker continues with download → audio extraction → Whisper → import.

State storage
workflows + workflow_steps + jobs

Timeline and progress are written into PostgreSQL for inspection.

Execution flow

Hover cards to read the role of each step
1
API

User submits a YouTube URL

The UI or API calls `POST /api/transcripts/youtube/schedule` with a YouTube link and language.

2
Application

TranscriptSchedulingService

Normalizes the media source, reuses existing transcripts if present, and returns an active workflow when one already exists.

3
Worker

Worker claims the workflow

The worker creates the first step: native_transcript_check.

Progress starts around 5%, and the workflow becomes visible in `workflows` and `workflow_events`.
4
Decision

Check for native subtitles

The worker runs `yt-dlp --write-subs --write-auto-subs --sub-langs all --sub-format vtt` on the YouTube URL.

If subtitles are found, the workflow takes the native branch. Otherwise it enters the manual path.

Native transcript branch

  • `available = true`
  • Queue `transcript.import`
  • Skip download/audio/Whisper
  • Finish as `succeeded` after import

Manual pipeline branch

  • `available = false`
  • Queue `youtube.download`
  • Queue `media.extract_audio`
  • Queue `whisper.transcribe`
  • Queue `transcript.import`
5
Persisted state

Every step writes to PostgreSQL

The workflow timeline, job progress, and final transcript are stored for later inspection and replay.

Useful tables: `workflows`, `workflow_steps`, `workflow_events`, `jobs`, `transcripts`.

What you can inspect

workflow status succeeded

Shows the overall outcome and the current step key if the workflow is still running.

workflow_events timeline

Contains human-readable messages like “Native transcript not available” or “Whisper transcription completed”.

jobs progress

Tracks the low-level job lifecycle, progress percentage, and job-specific error messages.

transcripts result

Stores the imported transcript, segment counts, word counts, language, and source metadata.

Quick debug commands

curl http://localhost:5000/api/workflows/<workflow-id>
curl http://localhost:5000/api/workflows/<workflow-id>/steps
curl http://localhost:5000/api/workflows/<workflow-id>/events
